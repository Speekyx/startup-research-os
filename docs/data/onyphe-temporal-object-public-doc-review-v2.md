## The exact discriminator

Service S at address A on port P is observed during governed window W. The SAME service is observed again AFTER W. Can a historical query restricted to W still retrieve the observation that happened inside W?

| if | then |
| --- | --- |
| yes | OBSERVATION_EVENT_APPEND or VERSIONED_OBSERVATION_HISTORY, and B2 may PASS |
| no | MAINTAINED_SERVICE_STATE_LAST_SEEN, and B2 FAILS |
| the documentation does not say | AMBIGUOUS, and B2 stays PARTIAL |

Every other temporal fact about the category is documented. What decides whether a windowed count means anything is what happens to a record that is observed twice, and that is a storage-model fact rather than a query-surface fact.

## The page most likely to answer it does not

**Major Changes For Historical Queries And Roadmap 2023.** Its title names historical queries, which is the surface the discriminator turns on. If any first-party page were going to state the storage model, this was it.

It contains no statement about whether a repeated scan of the same service creates a new document or updates an existing one, and none about versioning, append, overwrite, deduplication or last-seen semantics.

*What that establishes:* Not that the model is one thing or the other. That the public documentation does not say, after the question was put to the page written about exactly this surface.

## Inferences available and refused

- **historical data exists** — A category with seven months of history can be a stream of retained events or a maintained state with retained versions. Retention is not a storage model.
- **data collected wording** — -hourago is described as querying data collected in a past hour. A maintained record whose timestamp advanced into that hour would also match, so the phrase does not distinguish the two.
- **latest first default** — A default sort says which result is shown first. It presupposes more than one result exists to order, and says nothing about whether two results can describe the SAME service at two times.
- **older result retrievable** — -sort:0 reaching an older result is compatible with several older results for DIFFERENT services, which is what a maintained store also produces.
- **last observed wording** — This is the half of the timestamp sentence that points the other way, and it is not read as decisive either.

**Resolving an ambiguity in the direction that keeps a candidate alive is what this arc has refused five times. It is refused again here, and this time the refusal costs a whole documentation budget.**

*What would close it:* one first-party sentence stating whether a repeated scan of the same address, port and service creates a new document or updates an existing one. Retrieving records and inspecting whether two documents exist for one service would answer it. That is a measurement query, it destroys preregistration, and §A4 forbids it. The question is cheaper to ask than to buy.

*Not promoted because:* No page addresses the repeated-observation case, and every available wording is compatible with both models.
