## Subject: Three questions about datascan record semantics and scan configuration

We are documenting the methodology of published internet-scan datasets before using any of them as a measurement instrument, and your public documentation already answers most of what we needed. Three points we could not settle from it are below. All three are questions about how the data is structured and produced; none of them asks for records, for an account, or for anything commercial, and we are not asking you to assess our use case.

**1. DATASCAN RECORD LIFECYCLE.** For the datascan category, when the same service on the same address and port is observed by several successive scans, does each scan create a distinct document carrying its own collection timestamp, or is one document for that service updated in place so that its timestamp advances to the most recent observation?

> *Why we ask:* We would like to select the observations made during a defined past interval. Under the first model a service observed inside that interval stays selectable for it afterwards; under the second, a service observed inside it and again later would carry a timestamp outside it. We want to describe the data correctly rather than assume either.

**2. DATASCAN PORT SET.** Which TCP ports make up the datascan scan set, and is TCP port 22 among them? Separately: is the composition of that set recorded against a date or a configuration version, so that a reader can tell which port set was in effect during a given past scan cycle?

> *Why we ask:* The published scanned-ports page documents the set for the ctiscan category, and we did not want to assume the datascan configuration matches it, since the two differ in cadence, origin and retention. The second half matters because a set that changes over time makes a count comparable only within the period its configuration covers.

**3. FIELDS RETAINED BEYOND THIRTY DAYS.** For datascan records older than thirty days, which fields are removed? We are specifically asking whether these three survive: the scanned IP address, the collection timestamp, and the scanner node fields identifying which node and country performed the scan.

> *Why we ask:* Your retention documentation states that some fields are removed beyond thirty days and that the raw response field is truncated to 4 KB. The truncation is not a problem for us, and we are not asking about it again. What we cannot tell is whether the fields that locate an observation in identity, time and vantage are among the removed ones, which decides whether an older record can still be attributed to a period and a place.

If any of this is already published somewhere we did not find, a pointer is just as useful as an answer. And if any of it is not something you publish, that is a useful answer too and we will record it as undocumented rather than infer it.
