**Lifecycle:** `AMBIGUOUS`

If the queryable timestamp sits on a maintained record, a window filter selects services whose LATEST collection fell inside the window. A service observed during the window AND again afterwards then carries a later timestamp and drops out, so a windowed count systematically under-counts exactly the hosts that persist.

## The discriminating case

**A service is observed DURING window W, and observed again AFTER W.**

- *append model* — The observation inside W remains its own document carrying its own collection time, so a filter for W returns it. Correct.
- *maintained model* — The single record's collection time has advanced past W, so a filter for W does not return it. The service is missing from a count of what was observed during W, and every host that persisted is missing the same way.
- *which the documentation states* — **Neither.**

A service observed only before and only after W is excluded under both models, so testing that case discriminates nothing. It is the persisting host that separates them, and that is the common case rather than an edge one.
