## Why vantage is asked before pairing

A count of addresses that answered on a port is a count of addresses that answered FROM SOMEWHERE. Routing, filtering, blocklisting of scanner ranges and regional policy all mean that the same address can answer one vantage and not another.

**The trap it would recreate.** FRAME_INSIDE_THE_DEFINITION, from Mission 1.57. If each apparatus measures the hosts reachable from its own network, then each has put its frame inside the metric, and a proposition admitting both must define its population as a disjunction of two vantages — which relocates source attribution into the predicate exactly as the rejected web-traffic route did.

Two apparatuses probing from different vantages can still measure one construct if the construct's population is defined as globally routable addresses and both vantages are documented as unrestricted. What cannot be done is to assume it.

**The asymmetry with A7.** Lineage asks who produced the observation. Vantage asks from where. A LEVEL 2 lineage answer leaves vantage entirely open, and this mission found exactly that.

**What the documentation says.** It refers to the apparatus's own scanning technology, purpose-built for large-scale internet scanning, and to its scanning infrastructure.

**What it does not say:**

- where they are located
- whether probing originates from one network or several
