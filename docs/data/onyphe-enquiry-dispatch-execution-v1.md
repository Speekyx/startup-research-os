## What would satisfy the confirmation

- an explicit statement that the ONYPHE enquiry was actually sent
- the exact sender mailbox used
- confirmation that the send was manual rather than automated
- confirmation that it was sent once

Optional, and optional deliberately: sent_at, message id, mail provider, sent-folder evidence. §2 forbids demanding unavailable metadata merely to manufacture completeness. A manual send from a webmail client may expose no message id to the sender at all, and refusing to record the send for want of one would punish an honest report.

## The repository cannot verify a manual send

A reliability assessment is typed into this repository, so a terminal guard can require a person to be present. An outbound manual send happens entirely OUTSIDE the repository, in a mail client nothing here can observe.

No guard can establish that a manual send occurred. The repository can only record what the operator attests, and the honest response is to make the attestation level explicit rather than to pretend to proof.

*Which is why:* BODY_POST_SEND_VERIFICATION distinguishes BYTE_VERIFIED from OPERATOR_ATTESTED, and this record may never report the first on the strength of the second.

*The shape it shares with earlier missions:* Missions 1.36.1 and 1.42.1 both stopped because a value was authorised and the keystroke was not. This is the same boundary one step further out: the dispatch is authorised and the send has not happened, and here the repository could not even watch it happen.
