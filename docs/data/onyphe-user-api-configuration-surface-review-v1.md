## Why it was looked at at all

Its documentation says it returns a list of scanned ports. That is a CONFIGURATION fact rather than a measurement, so it looked like a route to the TCP/22 question that returns no host records, no banners and no counts.

**A route that returns no measurement is not thereby a safe route. Avoiding measurement contamination is one property; not exposing a credential is a different one, and the second is not implied by the first.**

## The credential finding

Exact wording: *View name, API key, remaining credit count, expiry date*

The provider's own description of this endpoint places an API key inside the set of things it shows. That is enough to classify the surface.

*What is not established:* Whether the key is literally present in the JSON payload as opposed to being the credential you authenticate with. The documentation does not settle it, and the distinction is not needed: a surface whose own documentation lists an API key among its contents is not one to call unattended in order to learn a port list.

**Never print, persist, log, echo, inspect, commit or expose a credential value. An endpoint documented as showing one is not probed to find out whether the documentation was loose.**

*And it was not checked either:* Determining whether an API key is configured in this environment would itself require reading a credential store, which §43 forbids and which would be a strange way to establish that credentials must not be exposed.

## The configuration semantic gap

`USER_API_PORT_LIST_RESOURCE_MAPPING = UNKNOWN`

This mission established from the Data Refresh Rate page that the port set differs BY CATEGORY (datascan 500, ctiscan TOP 100 / TOP 4000, and a separate TOP 25) and BY REGION (US/FR against SG/CN). An undifferentiated list of scanned ports cannot be attributed to any one of those without a mapping the documentation does not provide.

*The inference refused:* That a response saying scanned ports means the datascan US/FR 500-port set. It is exactly the transfer Mission 1.63 refused between ctiscan and datascan, arriving through a different door.

**Either alone would stop the call. The surface is credential-bearing, AND what it returns cannot be mapped to the resource the question is about. A future mission that solved only one of them would still not have a route.**

*What a future mission may not do:* Execute this endpoint because a port list would be useful. §52 permits a later mission to evaluate a narrowly operator-authorised call, and only if the fact cannot be obtained from safer public documentation and credential exposure is controlled. Neither condition is met.
