## BODY

We are evaluating published internet-scan datasets as measurement instruments for a research system, and are documenting each instrument's methodology before using it. Your published documentation already answers our questions about the scanned address range, the scanned port list, the per-record scan date and the structure of a response record, so those are not asked below. The following seven points are the ones we could not settle from the documentation. Each is a methodology question; none asks for data.

**1. SAMPLING.** Within a subnet being scanned in a given cycle, is every address in that subnet probed, or is a sample of addresses probed? If sampling is used at any stage, is the sampling rate or method published anywhere?

**2. PROBE ATTEMPTS.** At the transport layer, how many connection attempts does an address receive on a given TCP port within one scan cycle before it is treated as not answering? Is there a retry, and is there a timeout value?

**3. MEANING OF ABSENCE.** When an address does not appear with a given port in the data for a completed scan, is it possible to distinguish (a) probed and did not answer, (b) probed and filtered, (c) not probed in that cycle, and (d) excluded from scanning? Is any of that distinction exposed in the data?

**4. DUPLICATION.** Within one scan cycle, can a single address-and-port pair produce more than one record? If so, under what circumstances?

**5. RAW RESPONSE FIDELITY.** For an unparsed TCP response, is the stored raw field the bytes as received? Specifically: is there any size cap, truncation, whitespace trimming, re-encoding or normalisation applied before storage, and does any of it affect the first bytes of a response?

**6. VANTAGE.** From how many distinct network locations does the public scanning originate, and are they in more than one region? Are the source address ranges of the scanners published? Is there a documented route by which a network operator may request exclusion from scanning, and would an excluded range be distinguishable in the data?

**7. PORT SCHEDULE OVER TIME.** Your changelog records that the public scan port list has expanded on dated occasions. Two questions follow. Is the set of ports covered by a particular scan recorded anywhere, or exposed as metadata on that scan? And has any port ever been removed from the public scan list, or is expansion the only change made?

We are documenting methodology rather than requesting data, and we are happy to be pointed at a published page if any of the above is already answered somewhere we did not find. If any of these are not things you publish, that is a useful answer too and we will record it as undocumented rather than infer it.
