# Outbound dispatch envelope contract

Generated by `infrastructure/scripts/render_dispatch_envelope.py`. Do not edit.

**`outbound-dispatch-envelope@1.0.0`**

## `CONTENT_APPROVAL_IS_NOT_DISPATCH_APPROVAL`

An approved document may not be sent until a second immutable object identifies the approved content hash, the exact recipient, the exact outbound channel and the sender identity, and is itself approved. That second object is a dispatch envelope.

Mission 1.61 obtained an approval for a body. Missions 1.62, 1.63 and 1.64 each found that the body was ready and the action was not, for a different reason each time. An approval that names only bytes cannot express who receives them, through what route, or from whom.

*Not a registry entry:* That registry answers whether a measurement apparatus qualifies. This answers whether an outbound action may be taken on the operator's behalf. Putting an operator-action rule among apparatus requirements would make the registry two things.

## Three gates that stay separate

| gate | asks | granted by |
| --- | --- | --- |
| `CONTENT_APPROVAL` | are these the right words? | an operator approval naming the content hash |
| `RECIPIENT_ESTABLISHMENT` | who exactly receives it? | first-party published evidence, or an operator reading the exact string off a first-party page |
| `CHANNEL_AUTHORIZATION` | through what route, and as whom? | an explicit operator authorisation for this exact envelope |

**Never granted by:** a connector being present in the runtime; a connected account; a previous unrelated mail action; content approval; the word continue; the word go

## Envelope states

| state | meaning |
| --- | --- |
| `INCOMPLETE_RECIPIENT` | no recipient established; template only; no hash |
| `INCOMPLETE_CHANNEL` | recipient known, no permitted channel or sender bound; no hash |
| `READY_FOR_OPERATOR_APPROVAL` | every required field present; hash computed; awaiting an explicit dispatch approval |
| `APPROVED_NOT_SENT` | an operator dispatch approval matching the hash exists; nothing sent yet |
| `SENT` | recorded by the mission that actually sent it, never by the mission that prepared it |
| `SUPERSEDED` | replaced by a later envelope; never edited in place |

## Channel states

| state | meaning |
| --- | --- |
| `NOT_EVALUATED` | nobody has looked |
| `AVAILABLE_NOT_AUTHORIZED` | a mechanism exists and no operator authorisation for this research correspondence does. A connector present in the runtime starts here. |
| `OPERATOR_MANUAL_SEND` | the operator sends the message themselves from a mailbox of their choosing; the repository prepares the packet and never marks it sent |
| `AUTHORIZED_CONNECTOR` | an explicit operator authorisation exists for this exact envelope, naming this connector and this sender |
| `BLOCKED` | the route is refused |

## The envelope hash

Binds: `enquiry_document_id`, `enquiry_content_sha256`, `recipient_address`, `outbound_channel`, `sender_identity`, `subject`, `content_version`.

Excludes: `created_at`, `recipient_provenance`, `channel_authorization_basis`, `state`, `notes`. The hash binds the ACTION. When it was recorded, how the recipient was established and why the channel is permitted are provenance about the action rather than parts of it, and a timestamp in the hash would make an identical action hash differently on a different day.

Approval string: `APPROVE MISSION 1.65 DISPATCH <sha256>`

*Means:* send this exact action, once. *Does not mean:* send a second enquiry; retry; resend; send the other enquiry; send from a different mailbox.

## No envelope without a recipient

An envelope whose recipient is unknown is a TEMPLATE and its state is INCOMPLETE_RECIPIENT.

A hash is an approval handle. Producing one for an action that cannot be taken would let an operator approve something under-specified, and the missing field is the one that decides who reads the message.

## Sender identity

- **for a connector** — the specific operator-visible sender account must be identified before approval. Naming only the connector or the provider is not a sender identity, because it does not say which mailbox the recipient will see.
- **if it cannot be established** — CHANNEL_NOT_READY
- **for manual send** — OPERATOR_CHOSEN_MAILBOX_AT_SEND_TIME is permitted, and only for OPERATOR_MANUAL_SEND
- **why that flexibility is permitted here** — Under manual send the sender genuinely is not determined until the operator sends it, and binding a mailbox they did not choose would be recording a fact nobody established.
- **its cost stated** — An envelope carrying that placeholder binds content, recipient and channel but NOT the exact sender. Three of the four are pinned rather than four.
- **how to pin the fourth** — If the operator names the mailbox they will send from, a re-frozen envelope binds all four and carries a different hash. The earlier envelope is superseded rather than edited.
- **preference** — bind the exact sender where it is known
