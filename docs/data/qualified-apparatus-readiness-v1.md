### Added `APPARATUS_CONFIGURATION_MUST_BE_TIME_ADDRESSABLE`

A load-bearing scan-configuration fact, such as which ports a scan covered, must be attributable to the same observation period the measurement will come from, and attributable BEFORE retrieval. A configuration list published as a current reference establishes what is true today and binds no window.

*Demonstrated by:* Both investigated apparatuses. The anchor publishes a current port list and a changelog that dates the list's SIZE rather than its membership, and its per-scan coverage metadata is unpublished. The candidate publishes a port list carrying no date stamp, no version number and no scan-configuration identifier. Two independent apparatuses, the same gap.

*Distinct from:* OBSERVATION_ADDRESSABLE_EXPOSURE governs when the OBSERVATION happened and whether it can be selected. This governs when the CONFIGURATION applied. An apparatus can expose a perfect observation timestamp and still leave you unable to say whether it was probing the port during that window, and the second question is invisible if only the first is asked.

### Declined `FULL_FIDELITY_RETENTION_IS_PART_OF_ACQUISITION_CONTRACT`

It did not prove load-bearing. The retention question resolved favourably: the field carrying the predicate is named as truncated rather than removed, and the truncation does not reach the bytes the predicate tests. A rule is added where evidence demonstrates a distinct guard, and this mission's evidence demonstrated the opposite of the failure the rule anticipates.

*Recorded instead:* MAX_FULL_FIDELITY_RETRIEVAL_DELAY, frozen as a duration on the apparatus record, which is a constraint on a future acquisition rather than a general rule.
